## 2026-09-12

- **Fixed: vision pipeline page-1 error on Marathi land record PDF (`pune plot .pdf`).**
  Root cause: Gemma 3 at `temperature=0` is non-deterministic; on dense Marathi text it
  sometimes enters a repetition loop, hitting `max_tokens=4096` and producing truncated
  JSON (`finish_reason=length`). `VisionClient._parse()` returned this as a non-retryable
  failure, so the first truncated attempt permanently failed the page.
  Fix: `_parse()` now returns `(result, finish_reason)`; `extract()` retries when
  `finish_reason == "length"` (transient truncation). Other parse errors remain non-retryable.
  2 new tests added. 464 passed, 3 skipped, ruff clean. Live-verified on the actual PDF.
- Updated `.env`: `MAX_ATTEMPTS=3`, `REQUEST_TIMEOUT_SECONDS=180`.
- Updated `.agents/memory/vision-pipeline-status.md` with the diagnosis and fix.
- **Corrected model identity:** server laptop runs **Gemma 4 E2B** Q4_K_M (not Gemma 3 4B).
  3.46 GB file, 35 layers, 1 KV head, 512 sliding window, 20 shared KV layers.
  KV cache at 8192 context = ~31 MB (essentially free).
  Recommended context window: **8192** (pipeline needs ~5368 tokens for one PDF page).
  User's 2.1 GB VRAM = partial offload; needs `-ngl 99` for full GPU offload (~4.0 GB total).
